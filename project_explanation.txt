========================================================================
             FARMER CROP ADVISORY SYSTEM - PROJECT EXPLANATION
========================================================================

This document provides a comprehensive breakdown of the project, designed
to help you present it and explain each and every feature to evaluators.

------------------------------------------------------------------------
1. PROBLEM STATEMENT
------------------------------------------------------------------------
Modern agriculture is highly scientific, yet many farmers make critical 
decisions (such as what to grow, how much fertilizer to buy, and when to 
irrigate) based on guesswork or traditional routines. This leads to:

- Crop Failure & Low Yields: Planting crops in unsuitable soil profiles 
  (e.g., growing moisture-sensitive crops in sandy beds) or during the 
  wrong season.
- High Production Costs: Inability to scale fertilizer needs accurately 
  per acre. Farmers either over-fertilize (wasting money and damaging soil) 
  or under-fertilize (causing low yields).
- Subsidy Gaps: Inefficiency in manually calculating small-scale holder 
  subsidy discounts, causing financial strain on smaller farms.
- Resource Inequity (Canal Water Overdraft): Shared natural resources 
  like canal irrigation water are prone to race conditions. If multiple 
  farmers draw water from a shared reservoir concurrently without central 
  coordination, the reservoir will be overdrawn, leading to channel failures.
- Fragmented Systems: Lack of unified platforms that tie database records, 
  background monitoring, and active user dashboards together.

------------------------------------------------------------------------
2. OUR SOLUTION
------------------------------------------------------------------------
We developed the "AgriAdvisory System"—a web-based smart farming helper.
The application replaces the traditional terminal-only interface with:
1. A single-file Core Java Backend (CropAdvisoryApp.java) that starts an 
   embedded HTTP Web Server (com.sun.net.httpserver.HttpServer) and handles 
   computational logic.
2. A premium glassmorphic Single Page Application (SPA) Frontend (HTML, CSS, 
   JavaScript) served directly from the Java server, accessible in any browser.
3. Persistent Database Storage using SQLite via JDBC, with an automatic, 
   fault-tolerant CSV filesystem fallback.

------------------------------------------------------------------------
3. FEATURES & ARCHITECTURE EXPLAINED
------------------------------------------------------------------------

FEATURE 1: THE CROP CATALOG ENGINE (OOP & Polymorphism)
- Code Details: Represents the abstract base class 'Crop' implementing 
  the 'Cultivable' interface, with two subclasses:
  - 'FoodCrop': Adds category data (e.g. Cereal, Fruit, Vegetable).
  - 'CashCrop': Adds commercial target industry data (e.g. Textile, Oil).
- Nested Inner Class: 'Crop.FertilizerDetails' tracks NPK quantities 
  (Urea, DAP, MOP in Kg) required per acre for that crop.
- Web Implementation: Serves a complete database catalog of crops in a 
  responsive HTML table. Includes a popup modal form to dynamically register 
  new crop profiles, instantly updating the catalog database.

FEATURE 2: FARMER REGISTRIES (Inheritance & Subsidies)
- Code Details: Implements the abstract 'Farmer' class with two subclasses:
  - 'SmallFarmer': Specifically handles smaller holdings (<= 5 acres). 
    It overrides getFertilizerSubsidyRate() to apply a 30% discount on NPK.
  - 'LargeFarmer': Represents commercial operations (> 5 acres) receiving 
    standard market rates (0% subsidy).
- Nested Inner Class: 'Farmer.FarmRecord' serves as a recommendation log 
  receipt containing crop name, match score, estimated yield, and timestamp.
- Web Implementation: Lists all registered farmers, farm sizes, soil profiles, 
  and active subsidy rates in a table. Includes a "Register New Farmer" modal 
  form and a "Logs History" portal for each farmer.

FEATURE 3: CROP SUITABILITY ADVISORY (Algorithm & Math Scaling)
- Code Details: The suitability rating calculation executes a weighted scoring 
  algorithm out of 100%:
  - Soil Compatibility (Max 40%): Compares farmer soil to crop requirements. 
    Handles adaptability (e.g., loamy soil gets partial compatibility scores).
  - Growth Season Match (Max 30%): Compares current season (Kharif, Rabi, Zaid).
  - Water Level Match (Max 30%): Evaluates water access. Handles surplus 
    safely and penalizes deficits.
- Scaling Calculations: For the top recommended crop, the system automatically 
  calculates:
    - Expected Yield = Crop Yield Per Acre * Farmer Farm Size.
    - Urea/DAP/MOP Qty = Crop Requirement Per Acre * Farmer Farm Size.
    - Gross Cost = Sum of NPK weights multiplied by standard market unit prices.
    - Net Cost = Gross Cost minus the class-based Fertilizer Subsidy savings.
- Database Receipt Logging: The system saves the recommendation details to the 
  history database and lets you pull past recommendation cards via the frontend.

FEATURE 4: WEATHER ALERTS TICKER (Daemon Multi-threading)
- Code Details: Starts 'WeatherAlertDaemon' (extending 'Thread' with setDaemon(true)).
  This thread runs continuously in the background at set intervals (10s), simulating 
  sensor feeds by generating crop warning alerts (e.g., heatwaves, pest risks, 
  precipitation alerts, ideal sun).
- Web Implementation: Instead of logging directly to console (which interferes with 
  a server), the daemon stores alerts in a thread-safe Queue (ConcurrentLinkedQueue). 
  The web frontend polls this API and displays the newest alerts in a live scrolling 
  news ticker and alert board.

FEATURE 5: SHARED WATER ALLOCATION (Thread Concurrency Locks)
- Code Details: Demonstrates advanced thread synchronization using 'WaterAllocationTest'. 
  Simulates 5 concurrent threads (channels) requesting 15 KL of irrigation water 
  simultaneously from a shared reservoir of 50 KL.
- Synchronization Lock: The 'allocateIrrigation' method is 'synchronized' to 
  prevent race conditions. When the sluice gates are opened simultaneously via a 
  'CountDownLatch', the synchronized block ensures that:
  - Exactly 3 threads successfully decrement the reservoir (using 45 KL total).
  - The remaining 2 threads are denied water safely, preventing overdrafting.
- Web Implementation: The user clicks "Fire Simultaneous Sluice Gates" on the UI, 
  which triggers the backend simulation. The terminal output is captured and 
  streamed live inside a dark developer console element on the screen.

FEATURE 6: DATABASE PERSISTENCE (JDBC & SQLite)
- Code Details: Handles automated connection to a local SQLite database file 
  (crop_advisory.db) using JDBC driver reflection.
- Fault-Tolerance: If the SQLite driver is missing or connection fails, the 
  system catches the exception and falls back to buffered CSV text files 
  (crops.txt, farmers.txt, advisories.txt) using BufferedReader/BufferedWriter 
  so the application never crashes.
- Web Implementation: The UI queries the status endpoint and displays a green 
  or yellow pill representing if JDBC SQLite is active or if it fell back to CSV files.

4. TECH STACK SUMMARY
------------------------------------------------------------------------

- Database Link: JDBC SQLite Driver.

- Concurrency: CountDownLatch, ConcurrentLinkedQueue, Thread Synchronized locks.
